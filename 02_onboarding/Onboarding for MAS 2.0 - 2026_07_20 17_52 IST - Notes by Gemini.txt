Verifier Design and Strategy
* Transition to multi-dimensional verifiers combining structural checks, partial oracle validation, and anti-reward-hacking mechanisms.
* Target 20-50% multi-agent success rate and significantly lower single-agent success rate to improve evaluation utility.
* Utilize partial oracle solutions by verifying random data subsets to ground LLM outputs without requiring comprehensive golden oracles for all tasks.
* Prevent false failures by ensuring agents consistently generate output files within designated directory structures.


Technical Implementation Standards
* Mandate folder architecture placing inputs in environment/input_artifacts and outputs in logs/agent.
* Standardize all verifier scripts to the filename verify.py.
* Require rubric_manifest.json in the root folder, detailing test logic in natural language.
* Modularize LLM judge logic into multiple parallel API calls to reduce hallucinations and improve objectivity.


Task Quality and Metadata
* Select newer or obscure data sources to prevent contamination from LLM training sets.
* Prohibit rubric weightages; assign equal weights to each component to align with client pipeline requirements.
* Update task TOML metadata only after gathering execution logs to ensure alignment with trajectory data.
* Generate 100 new tasks, initiating with a 50-task batch in the labeling tool.


Operational Updates
* Shift operational environment to cloud service log access and centralized labeling tool submissions to prevent file editing conflicts.


Documentation and workflow updates

* Labeling tool task completion targeted by end of day.
* Meeting recording distribution pending file processing.


Rework submission strategy
